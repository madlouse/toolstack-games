# Toolstack Lab · AI 3D 游戏合集

> **Live:** https://games.gettoolstacklab.com/ · evidence: [evidence/LIVE.md](evidence/LIVE.md)

Public static hub for browser 3D games made by [Toolstack Lab](https://gettoolstacklab.com).

- **Target host:** `https://games.gettoolstacklab.com` (Vercel static)
- **Target repo (later):** `madlouse/toolstack-games`
- **Stack:** plain HTML/CSS/vanilla JS, generated by `build.mjs` from `data/games.json`
- **Privacy:** no cookies, no third-party scripts/fonts, no personal data. `localStorage` only stores *this visitor’s* “recently played” list on their device.

## Why

A single light page that lists our live games, with real screenshots, controls, licence/source, and an on-click iframe play path — without a framework or analytics SDK.

## Commands

```bash
node validate.mjs          # fails if license/source/licenseUrl missing
node build.mjs             # validate + write dist/
node scripts/update-stats.mjs path/to/export.json
npm run capture            # Playwright screenshots from live game URLs (optional refresh)
npm run indexnow           # re-submit sitemap URLs to IndexNow (Bing) after a content deploy
```

Serve `dist/` with any static host. Locally:

```bash
npx --yes serve dist -p 4173
# or: python3 -m http.server 4173 --directory dist
```

## Popularity sort

Home cards sort by:

```
score = plays * 3 + visits
```

Counts live in `data/stats.json`. Seed for this MVP (external visits, 14 days 2026-10-16 → 2026-10-29, Asia/Shanghai) comes from `../analytics/TABLE-10-16_to_10-29.md`:

| slug | visits | plays |
|------|--------|-------|
| spud-fling | 104 | 0 (unknown) |
| pips-bloom-isle | 10 | 0 (unknown) |

`plays` stayed `0` because playtime export was unavailable (Analytics Engine SQL 403). Do not invent numbers.

Client-side “recently played” is **not** a popularity signal — it never leaves the browser.

### Counting basis (what a visit is)

The hub pages themselves never count anything: no beacon, no analytics request (gate `beacon-count`, check
`beacon.hub-page`). Counting happens only inside our own games, on their own web addresses, with Cloudflare's
cookie-free Web Analytics.

- **Unit:** one Web Analytics page-load (`rumPageloadEventsAdaptiveGroups` → `sum.visits`) of a game's page. On the hub
  the game iframe loads only when the player presses Play, so **a hub play = one game page-load**, counted like a
  direct visit. Headless/bot user agents are dropped as internal (`../analytics/pull.py`).
- **Per game, exactly one beacon per page-load**, chosen by the hub iframe's `embedQuery` (data/games.json, allowed
  values checked by validate.mjs):

  | game | direct visit | hub play (iframe) | counted from |
  |---|---|---|---|
  | spud-fling | own tag (site 458b…, token ca5fd27c…) | `?src=hub` → own tag | site 458b…, all hosts |
  | pips-bloom-isle | own tag (site 3e2e…, token cece3f04…); the zone beacon script also loads but sends nothing | `?internal=1` → own tag skipped; the Cloudflare zone beacon (site 263d…, token d6efacb3…) is the only one | site 3e2e… + site 263d… rows with requestHost bloom-isle.gettoolstacklab.com |
  | merge-tiles (third-party) | not counted | `?internal=1`, no beacon | — |
  | moon-rover (third-party) | not counted | `?internal=1`, no beacon | — |

Classics stay uncounted on purpose. The home Classics shelf, the All games page, About, and each classic's page say "Visit counts cover Toolstack Lab's own games only." Do not invent a count for them.

- **Hub vs direct:** the beacon drops the query string from the page URL and Web Analytics has no query dimension, so
  `?src=hub` itself never reaches the data (it only selects the behaviour). The split is the **referrer host**: our own
  games' iframes send only the hub's origin as referrer (`referrerpolicy="strict-origin"`; third-party iframes keep
  `no-referrer`), so a hub play has `refererHost = games.gettoolstacklab.com`; anything else is direct.
- **Not double counted:** each page-load sends one beacon POST (gate `beacon.count`; direct Pip has two beacon scripts
  but only one posts). Zone rows of hosts other than bloom-isle (e.g. spud-fling.gettoolstacklab.com) are never added to
  a game.
- **History:** before the 2026-10-30 hub deploy every hub embed used `?internal=1`, so Spud hub plays were not counted,
  and Pip hub plays reached only the zone site, which `pull.py` did not read (and most of those were our own headless
  gate runs). Gate tools now abort every beacon POST, so gate runs record nothing.

### Updating counts later

1. Export `{ "slug": { "visits": N, "plays": M }, ... }` from Cloudflare Web Analytics events or a tiny Vercel function + free store.
2. Run `node scripts/update-stats.mjs export.json`.
3. Rebuild. The merge replaces absolute counts per slug; `_meta` is preserved unless the export supplies one.

Real counters are **docs only** in this MVP — not built.

## Add a game

1. Confirm the game passes [CONTENT-POLICY.md](./CONTENT-POLICY.md) (self-made / CC0-PD / OSS with commercial+embed rights; record proof).
2. Append an object to `data/games.json` with every required field (`slug`, `title`, `pitch`, `description`, `controls`, `tags`, `url`, `embed`, `thumbnail`, `screenshots` ≥3, `license`, `licenseUrl`, `source`, `author`, `added`, `status`). A third-party (non self-made) game also needs `licenseEvidence`, `copyrightNotice`, `modifications` and an `https://` `source`; its credits block is rendered from these fields. Run `npm test` (validate fixtures) and `node test/build-fixture.mjs` after changing `validate.mjs` or `build.mjs`.
3. Capture ≥3 screenshots from the live URL (`npm run capture` or equivalent) into `assets/games/<slug>/`.
4. Add `{ "visits": 0, "plays": 0 }` under that slug in `data/stats.json` (or real numbers only).
5. If the game origin is new and `embed: true`, add it to `frame-src` in `vercel.json`.
6. `node validate.mjs && node build.mjs`.

## Nonogram levels

Picture-logic nonogram levels live under `/nonogram/`. `scripts/nonogram/generate.mjs` builds `data/nonograms.json` from a fixed seed. `scripts/nonogram/solver.mjs` is a separate line solver plus backtracking counter (it stops at two solutions). `node build.mjs` writes one static page per level, plus size and difficulty indexes, into `dist/`.

```bash
node scripts/nonogram/generate.mjs
node scripts/nonogram/verify.mjs
node build.mjs
```

Running the generator twice rewrites the same bytes.

### Daily snapshot

`node scripts/zpc-snapshot.mjs` appends one row to `data/zpc-snapshots.csv`:

```
date,page_count,organic_visits
```

`date` is the Asia/Shanghai calendar day. `page_count` is the number of `<loc>` entries in `dist/sitemap.xml`, so build before you snapshot. `organic_visits` stays blank when `ZPC_ANALYTICS_TOKEN` is unset. The script does not read secret files and does not call an analytics API. The Cloudflare token still lacks Account Analytics Read permission, so a visit count is not available yet. The script exits 0 with no token.

## IndexNow (Bing)

Bing (and other IndexNow engines) learn about new/changed pages without a Bing Webmaster login.

- Key file: `data/indexnow.key` (32 hex chars, public by design). `build.mjs` writes it to `dist/<key>.txt`.
- After each content deploy that changes URLs, run:

```bash
npm run indexnow
# or: node scripts/indexnow.mjs --sitemap dist/sitemap.xml
```

The script POSTs every `<loc>` from the live sitemap (max 10,000) to `https://api.indexnow.org/indexnow`. HTTP 200/202 means accepted.
